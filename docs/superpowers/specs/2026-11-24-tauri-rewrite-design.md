# Koteyye Media Studio 2.0 — переписывание на Tauri + Rust

Дата: 2026-11-24
Статус: на утверждение

## Зачем

Существующий десктопный клиент (Electron + React, v1.1.0) устарел: его контракты
не соответствуют текущему API OpenRouter, стек тяжёлый, а функционал ограничен
изображениями и видео. Решение пользователя: полностью снести Electron, написать
новое приложение на Tauri 2 + Rust, пересмотреть дизайн, перейти на единственного
провайдера **Cheaper Inference** (CI) и добавить генерацию аудио. OpenRouter в
новой программе не используется.

## Цели

1. Новое приложение целиком на Rust: Tauri 2 (ядро) + Dioxus (UI, компилируется
   в WASM и работает внутри webview Tauri). От Electron не остаётся ничего.
   JavaScript/TypeScript нет; допустимы минимальные wasm-bindgen-обёртки над
   web--API (canvas, Web Audio), если без них не обойтись.
2. Единственный провайдер — Cheaper Inference (`https://api.cheaperinference.com`):
   - **Изображения**: генерация (`POST /v1/images/generations`) и редактирование
     по референсам (`POST /v1/images/edits`, JSON-вариант с `input_references`).
   - **Видео**: `POST /v1/videos/generations` — синхронный запрос; режимы
     text-to-video, image-to-video (`image_url`), reference-to-video
     (`input_references`).
   - **Аудио**: `POST /v1/audio/speech` — три режима: озвучка (TTS, выбор голоса),
     музыка (music-v2/2.5), звуковые эффекты (sound-effects-v2).
3. Все результаты автоматически сохраняются в локальную папку; история хранится
   локально и ссылается на локальные файлы (CI хранит файлы лишь 7 дней).
4. Современный UI «Студия» (утверждённые мокапы в `.superpowers/brainstorm/`):
   сайдбар, промпт, чипы параметров, результат на всю ширину, лента «Недавние».
5. Две темы (тёмная «Графит», светлая «Воздух») с фирменным медным акцентом
   `#e05616` (hover `#ff7333`) — цвет из старого приложения.
6. Локализация ru/en, как в старом приложении.
7. Надёжность: долгие видеогенерации не блокируют UI и переживают перезапуск
   (восстановление через `GET /v1/generations/{request_id}`).
8. Автообновление через GitHub Releases (tauri-plugin-updater, подпись сборок).

## Не-цели

- OpenRouter и любые другие провайдеры (абстракция провайдера не требуется, но
  код CI-клиента не должен расползаться по UI — слой изолирован).
- Распознавание речи (STT), realtime-голос, клонирование голоса — возможен later.
- Аудио-референс для видео (функция v1.1.0) — убран осознанно, возможен later.
- Рисование маски кистью — в 2.0 маска только загрузкой PNG-файла.
- Мобильные платформы, облачная синхронизация, аккаунты/телеметрия.
- ImgBB и любые внешние хостинги картинок: CI принимает data-URL напрямую,
  для больших файлов — собственный `POST /v1/uploads` (лимит 4 МБ).

## Анти-цели

- «Тонкий прокси»: Rust не должен быть просто обёрткой над fetch — вся тяжёлая
  логика (HTTP, ретраи, файлы, история) в ядре.
- Потеря результатов: локальная копия первична, истечение 7-дневного хранения CI
  не должно ничего ломать.
- Замороженный UI во время генерации (видео может делаться минуты).

## Ограничения

- **CI API** (проверено по документации и живому каталогу):
  - Аутентификация: `Authorization: Bearer ci_live_...` (или `x-api-key`).
  - Каталог: `GET /public/models` без ключа; `GET /v1/models` с ключом.
    Поля: `model_type` (image/video/speech/…), `features` (напр. `image-input`),
    `supported_endpoints`, `media_prices` (цена за секунду/символ по разрешению
    и наличию звука), `provider_name`, `logo_url`.
  - Видео синхронное: один блокирующий запрос, в ответе файлы + `request_id` +
    `billing`. Повторная выдача файлов: `GET /v1/generations/{request_id}`
    (ссылки живут 1 час, файлы 7 дней).
  - Биллинг: `billed_cost_usd` — строка с 6 знаками; заголовок
    `x-ci-billed-cost-usd` на аудио/видео.
  - **Баланс**: `GET /v1/account/balance` требует scope `account:read`, которого
    нет у ключа по умолчанию. Обычный inference-ключ баланс не прочитает.
  - Аудио: `input` 1–4096 символов, `voice`, `response_format`, `speed`;
    дополнительные свойства пробрасываются провайдеру.
  - Изображения: `n` 1–10, `size`, `quality`, `response_format`; edits —
    `input_references: string[]` (URL или data-URL), `mask_reference`.
- **Платформы**: macOS и Windows (как у старого приложения).
- **Стек**: Tauri 2 (стабильный), Rust stable, Dioxus (WASM frontend), Vite не
  используется — сборка UI через `dx`/trunk.
- Ключ и настройки хранятся локально; ключ — по возможности в системном keychain.

## Подходы к архитектуре

### C · Полностью Rust (Tauri + Dioxus) — выбран пользователем

Всё приложение на Rust: ядро Tauri (HTTP, файлы, история, джобы) и UI на Dioxus,
который компилируется в WASM и рендерится в webview Tauri. Один язык, один
инструментарий, максимальная отдача от Rust-скиллов.

Почему выбран: осознанное решение пользователя — «Rust + Tauri, всё на нём».
Dioxus даёт компонентную модель (сигналы, хуки, RSX), близкую к React, что
упрощает перенос UI-паттернов старого приложения; роутер и desktop-поддержка
есть из коробки.

Риск (принят): экосистема богаче у React, часть UI-решений (waveform, drag-and-drop)
придётся делать через web-sys/wasm-bindgen или небольшие JS-обёртки.

### A · React + «толстое» Rust-ядро — отклонён

Был рекомендован как более быстрый и предсказуемый путь (знакомый React-стек,
богатая UI-экосистема). Пользователь предпочёл единый Rust-стек.

### B · React + «тонкий» Rust-слой — отклонён

Rust только проксирует HTTP, оркестрация в TS. Теряется смысл переезда на Tauri:
долгие запросы и восстановление сложнее делать в JS, надёжность ниже.

## Архитектура (как строим)

### Структура проекта

Новый проект в том же репозитории (старый код Electron удаляется):

```
koteyye-media-studio/
├── src-tauri/            # Rust-ядро Tauri (backend-команды)
│   ├── src/
│   │   ├── main.rs
│   │   ├── api/          # CI-клиент: images, videos, audio, models, generations
│   │   ├── catalog.rs    # каталог моделей, кэш, фильтрация по типу/возможностям
│   │   ├── jobs.rs       # оркестрация генераций, ретраи, восстановление
│   │   ├── storage.rs    # SQLite: история, настройки
│   │   ├── files.rs      # сохранение медиа, папка пользователя, имена файлов
│   │   └── events.rs     # события в frontend
│   └── tauri.conf.json
├── ui/                   # Dioxus-приложение (Rust → WASM), общий крейт с ядром
│   ├── src/
│   │   ├── main.rs
│   │   ├── screens/      # Studio (image/video/audio), History, Settings, Onboarding
│   │   ├── components/   # chips, model-dropdown, players, upload, recent-strip
│   │   ├── state.rs      # сигналы/контекст Dioxus
│   │   └── i18n.rs       # ru/en
│   └── assets/           # CSS-токены тем, иконки
├── Cargo.toml            # workspace: src-tauri + ui (+ общий крейт типов)
└── docs/
```

Типы запросов/ответов CI и модели истории — в общем крейте, который используют
и ядро, и UI; UI вызывает команды Tauri через `tauri-sys`/wasm-bindgen glue.

### Rust-ядро

- **HTTP**: `reqwest` (async, tokio). Таймаут видеозапроса — большой (минуты),
  при обрыве/таймауте — восстановление через `GET /v1/generations/{request_id}`.
- **История**: SQLite (`rusqlite`). Запись на каждую генерацию: id, тип, режим,
  модель, промпт, параметры, статус, `request_id`, локальные пути, цена, время.
  Статусы: pending → completed/failed. При старте — recovery pending-записей.
- **Файлы**: автосохранение в папку пользователя сразу после получения результата;
  имена вида `image-<timestamp>.png`, `video-<id>.mp4`, `audio-<id>.mp3`.
- **События**: `generation:started/progress/done/failed`, `balance:updated` —
  через `tauri::Emitter`.
- **Настройки**: папка, язык, тема, ключ. Ключ — в системный keychain (`keyring`),
  fallback — зашифрованное локальное хранилище.

### Frontend (Dioxus, Rust → WASM)

- Dioxus (CSR внутри webview Tauri), состояние — сигналы и контекст.
- Экраны и навигация — по утверждённым мокапам (см. ниже); роутер Dioxus.
- Плееры: видео — нативный `<video>` через web-sys; аудио — кастомный плеер
  с волной (canvas + Web Audio через wasm-bindgen; допустима тонкая JS-обёртка
  типа wavesurfer, если своя реализация неоправданно дорога).
- Drag-and-drop изображений в промпт-зону (видео i2v/r2v, изображения-референсы) —
  нативные DOM-события через web-sys.
- Оценка цены до генерации: из `media_prices` каталога (разрешение × звук × длительность).
- Стили — обычный CSS с переменными тем (те же токены, что в мокапах).

### Поток данных

UI → `invoke("generate_image", …)` → Rust → CI → файл на диск → событие в UI →
запись в истории. Видео: то же, но запрос долгий; UI показывает прогресс-состояние,
окно можно закрыть — джоб живёт в Rust-ядре.

## UI — утверждённые решения (мокапы)

1. **Студия** (вариант A + A1): сайдбар слева (Изображения, Видео, Аудио, История,
   Настройки), в центре промпт → строка чипов (модель, размер, ratio, seed, «+ ещё»)
   → кнопка «Сгенерировать» → результат на всю ширину → лента «Недавние» внизу.
   Правой панели параметров нет. Изображения: табы «Из текста / По референсу»,
   в режиме редактирования — загрузка референсов и PNG-маски файлом.
2. **Аудио** (S1): один раздел «Аудио», внутри табы «Озвучка / Музыка / Звуки».
   Озвучка: голос, формат, скорость; музыка/звуки: длительность. Плеер с волной.
3. **Видео** (V2): явные табы «Из текста / Из изображения / По референсам».
   i2v: первый/последний кадр; r2v: несколько референсов. Чипы: длительность,
   разрешение, ratio, звук вкл/выкл. Под каждый режим — свой набор моделей.
4. **История** (H2): список-таблица (превью, промпт, модель, дата, цена, действия
   📂 ↻ 🗑), фильтры по типу, поиск по промпту. «Повторить» переносит промпт и
   параметры в студию.
5. **Выбор модели** (M1): умный дропдаун из чипа — поиск, группировка по
   провайдеру, цена и возможности в строке.
6. **Темы**: тёмная «Графит» (#0a0c10 база) и светлая «Воздух» (#f5f6f8 база),
   акцент `#e05616`, hover `#ff7333`. Переключение в настройках (+ системная).
7. **Настройки**: API-ключ CI с проверкой подключения, папка сохранения, язык
   ru/en, тема, расход/баланс (см. открытый вопрос).
8. **Онбординг** (первый запуск): ввод ключа → выбор папки → готово. Каталог
   моделей можно показать ещё до ключа (`/public/models`).

## Что остаётся на усмотрение строителя

- Конкретные крейты и их версии (reqwest/tokio, rusqlite, keyring, dioxus,
  tauri-sys и т.п.), схема сборки WASM-фронтенда в дистрибутив Tauri (dx/trunk).
- Реализация waveform, точные имена Tauri-команд и схем событий.
- Точные схемы ответов CI (проверить живыми запросами с ключом пользователя).
- Обработка ошибок, ретраи, тесты, CI-сборка под macOS/Windows.
- Миграция: старый код удаляется; история старого приложения не переносится
   (другой провайдер), но локальные файлы пользователя не трогаем.

## Решённые вопросы (бывшие открытые)

1. **Баланс — гибридный, опциональный.** По умолчанию показываем локальный расход
   (агрегация биллинга запросов в SQLite, работает с любым ключом). Если пользователь
   хочет видеть настоящий баланс CI — предлагаем создать ключ со scope
   `account:read` (подсказка в настройках/онбординге). При наличии такого ключа
   показываем баланс через `GET /v1/account/balance`; при 403 — фолбэк на локальный
   расход. Индикатор в ленте «Недавние» остаётся, событие `balance:updated` тоже.
2. **Редактирование изображений**: явные табы «Из текста / По референсу» (как у
   видео). Маска в 2.0 — загрузка готового PNG-файла (`mask_reference`), без
   рисования кистью (рисование — later). Модели фильтруются по наличию
   `/v1/images/edits` в `supported_endpoints`. «Повторить» из истории для
   edit-записей восстанавливает референсы и маску.
3. **Аудио-референс для видео** (был в v1.1.0) — убран из 2.0 осознанно; при
   необходимости вернём later.
4. **Автообновление — оставляем**: `tauri-plugin-updater` + GitHub Releases +
   подпись сборок, кнопка проверки в настройках. Переход пользователей v1 на 2.0 —
   ручная установка (другой установщик), бесшовный апдейт не планируем.

- Лента «Недавние» под холстом студии — остаётся (предложена, не отклонена).
